Synchronization corrections:
1. D3D_BlockOnTime previously submitted/drained all GPU work unconditionally.
   Original 320997..3209AE reads the real completion word through device+30,
   then returns when (issued-requested) >= (issued-completed), using unsigned
   32-bit subtraction. The native binding now performs that exact completed-
   timestamp check after polling real native completion events. Pending requests
   retain the real full-completion wait. An existing GPU diagnostic now also
   checks completed, pending and wrapped timestamps without adding fences.
2. Method 110 (WAIT_FOR_IDLE) is GPU command ordering, not a CPU wait. Both native
   graphics paths now submit pending draws to their single D3D11 immediate
   context. Private uploads retain each draw's data; D3D11 handles native resource
   dependencies. CPU-visible semaphores/callbacks still use real completion
   events, and explicit CPU waits/readbacks retain their completion behavior.
   A nonblocking end-of-submission event keeps IsBusy aware of the whole native
   batch, including work after the last guest semaphore. The existing 64-event
   queue remains bounded; there is no per-barrier CPU completion wait.

The D3D11 mapping relies on the fixed observable pipeline order and native
read-after-write dependency handling in Microsoft's functional specification,
sections 4.2 and 5.6.7:
https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm
Flush is asynchronous; explicit event queries provide CPU completion:
https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-flush
Independent register/behavior reference: NV097_WAIT_FOR_IDLE=110 and the GPU
surface-update method in xemu's pgraph.c (not an original-game visual reference):
https://github.com/xemu-project/xemu/blob/master/hw/xbox/nv2a/pgraph/pgraph.c

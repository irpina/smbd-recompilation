Scope and method

Reviewed src interfaces and implementation families for executable validation,
address/layout preservation, control-flow recovery, instruction lowering, native
services, rendering, audio, input, installation, settings and diagnostics. Used
the supplied XISO and bounded original-XBE disassembly, the existing indexed
analysis, a sequential Clang static-analyzer pass over Windows C++ translation
units, and focused native diagnostics. Generated data and diagnostic cases stay
under build/. No Python, runtime instruction decoding or new test framework.

Existing edits to PLAYTEST.txt, boot.cpp, xbox.cpp and xbox.h were present when
this audit began and were preserved. This report covers the working-tree source.

Corrections

1. Pending I/O could signal freed/reused guest objects (high priority).
   queue_io retained a host OpenFile but kept only unreferenced guest file/event
   addresses. NtClose could recycle those slots before dispatch_io wrote their
   completion signals. Pending requests now retain both guest objects and release
   them after completion. File-handle waits now retain the enclosing FILE_OBJECT
   when waiting on its event at +0x38. Immediate asynchronous failures and empty
   requests also restore the file completion signal instead of leaving it reset.
   The new check-services command uses real asynchronous reads from the verified
   XISO, closes both handles before collecting completion, allocates another
   object, checks original XBE bytes and event signals, and checks final release.
   It uses isolated output storage and does not boot the game or open audio.
   Contracts: Xbox kernel NtReadFile ordinal 219, NtClose 187, NtOpenFile 202;
   native Xbox FILE_OBJECT packing and existing original SDK callers.
   Sources:
   https://raw.githubusercontent.com/XboxDev/nxdk/master/lib/xboxkrnl/xboxkrnl.h
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntreadfile
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-obdereferenceobject

2. Optimized sprite search changed a defined CPU flag (low priority).
   The original 00073900 exits a successful search after CMP tag,needle. The
   replacement used logic_flags, which retains AF, while an equal CMP clears it.
   The successful path now uses sub_flags for the original equal comparison.
   The existing CPU diagnostic exercises this with every arithmetic flag set.
   Evidence: build/logs/correctness-audit-sprite-original.json; the complete
   original routine signature remains checked by the lowering code.

3. Controller rumble stopped after an invented one-second timeout (medium).
   Original XInputSetState at 00342317 sends motor state without a duration.
   Input::rumble supplied 1000 ms to SDL and never renewed it. The input provider
   now keeps the requested motor state, renews before SDL expiration, clears it
   on disconnect and honors an explicit zero-motor command. The virtual-device
   input diagnostic checks persistence beyond one second and explicit stopping.
   SDL also handles device-specific hardware refresh; duration zero would disable
   that resend in the pinned SDL implementation, so it is not used as a shortcut.
   Sources (the SDL revision matches CMakeLists.txt):
   https://raw.githubusercontent.com/libsdl-org/SDL/829a65d769d935c4852f8159e964312c0957260a/src/joystick/SDL_joystick.c
   https://raw.githubusercontent.com/libsdl-org/SDL/829a65d769d935c4852f8159e964312c0957260a/include/SDL3/SDL_gamepad.h

4. Cubemap mip chains ignored Xbox face alignment (medium).
   GPU range calculation and native upload treated six faces as tightly packed.
   Each Xbox face starts on a 128-byte boundary, including its whole mip chain.
   Both paths now account for that spacing. The texture-cache diagnostic draws
   all six faces at each of two mip levels, with distinct padding bytes so a
   wrong face offset cannot accidentally pass. No claim is made that this format
   was the cause of an observed title scene defect; this fixes the supported
   renderer's cubemap data contract.
   Sources:
   https://raw.githubusercontent.com/xemu-project/xemu/master/hw/xbox/nv2a/nv2a_regs.h
   https://raw.githubusercontent.com/xemu-project/xemu/master/hw/xbox/nv2a/pgraph/vk/texture.c

5. Replay rejected resources below the capture writer's limit (medium).
   Captures permit 128 MiB of binary data, while replay rejected cumulative
   resource reads above 64 MiB. The reader now uses the writer's 128 MiB total
   limit and retains its separate 64 MiB per-resource bound. It still streams
   records and enforces resource, draw and stream limits.

6. Disc filenames could become Windows drive-relative output paths (high).
   Disc::directory rejected separators and dot components but accepted colons.
   A name such as C:escape.txt is a Windows path/stream expression, not a safe
   extraction component. Colons are now rejected when directory nodes are read,
   before extraction joins a filename to its output directory. A small synthetic
   XISO directory reproduces acceptance by the old tool and rejection after the
   fix; it does not contain game media. The supported disc remains accepted.
   Source:
   https://learn.microsoft.com/en-us/cpp/standard-library/path-class

7. Texture border addressing silently used black instead of the guest color
   (medium). Border addressing was supported, but NV097's per-stage border-color
   method at 1B24 + stage*40 was absent from RenderState and the native sampler.
   The bridge now carries that color into D3D11 and includes it in the pipeline
   cache key. The texture diagnostic checks two distinct colors outside the
   image, including a color change on an otherwise identical sampler.
   Source:
   https://raw.githubusercontent.com/xemu-project/xemu/master/hw/xbox/nv2a/pgraph/gl/texture.c

8. Querying an aliased allocation indexed outside its page metadata (high).
   NtQueryVirtualMemory used allocation(), which normalizes native guest RAM
   aliases, then subtracted the physical allocation base from the unnormalized
   query address. A valid 80000000/F0000000 alias therefore produced an enormous
   page index. It now uses the physical offset for metadata lookup and preserves
   the requested alias in returned region addresses. check-services exercises an
   interior address in the same allocation through all three supported mappings.

Static-analysis safeguard

The analyzer flagged a possible oversized shift in register-preservation proofs
(value_preserved, decoder.cpp). Both preservation helpers now reject register
indices outside the eight guest general registers before using a bit mask. The
existing recovery callers already try to establish that invariant; this check
makes it local and prevents undefined behavior if an invalid index reaches them.
It is recorded separately from the eight behavior defects above.

An investigated behavior intentionally preserved

Audio::positions adds loop_start after reducing play+ahead modulo loop_size.
Although subtracting loop_start first looks more conventional, original
0033E494 explicitly divides the unadjusted sum at 0033E518 and then adds the
loop start at 0033E52C. Changing this would break agreement with this executable.
Evidence: build/logs/correctness-audit-audio-position-core.json.

Acceptance limits

knowledge/runtime_progress.json already records incomplete full-game validation
and an unmet 360 Hz target. Native game batch builds are explicitly Windows x64
only in CMakeLists.txt. Linux/macOS service, graphics and CPU backends required by
DESIGN.txt are not implemented/validated by these changes. POSIX diagnostic code
was reviewed but cannot be compiled or run against native POSIX APIs on this
Windows host. Original-video parity, all stages/party games and Mac hardware
performance remain separate acceptance work.

Additional corrections

1. Synchronous unbuffered reads/writes and FilePositionInformation seeks skipped
   the sector checks applied to asynchronous I/O. One shared predicate now checks
   both kinds of transfers and seeks: 2048-byte sectors on the mounted disc and
   512-byte sectors on native storage. Buffered transfers retain byte addressing.
   Failed transfers report zero bytes and leave the position/file size unchanged.
   Original call evidence: IAT 347554/347558; read 308E4E and write 30900E.
   The original code's ordinary heap buffers remain valid; host DMA pointer
   alignment is not imposed on the guest's buffered native handles.

2. A request such as UINT32_MAX bytes reached the checked page-rounding helper
   and stopped execution instead of returning allocation failure. The allocator
   now checks the bounded RAM size, alignment and physical-address limits first.
   System/contiguous allocation returns null; NtAllocateVirtualMemory returns
   STATUS_NO_MEMORY. No allocation is installed on failure. Original 305F7A
   calls NtAllocateVirtualMemory through IAT 3475C4 and tests its failure result
   at 305F80/305F82, translating failure to null at 305F8F.

3. NtFreeVirtualMemory could find an allocation using a normalized alias, then
   calculate page iterators using the unnormalized address. Oversized decommit
   ranges could also overflow before validation. It now rejects addresses and
   byte counts outside the reservation before rounding or forming page iterators.
   Valid decommit still changes only the selected pages; release still frees the
   complete original reservation.

4. Allocation lookup discarded every address's high nibble, allowing an unmapped
   prefix such as 1xxxxxxx to identify an unrelated live allocation. Lookup now
   accepts only low RAM and the 8xxxxxxx/Fxxxxxxx mappings installed by the native
   memory bridge. Queries for other prefixes fail rather than reporting RAM or
   allowing a free/protection operation to target it.

5. Window presentation reused the 4096-pixel guest-image guard, so a valid 5120-
   pixel desktop window stopped rendering. Presentation now uses the D3D11
   feature-level-11 texture dimension limit (16384). Guest image/texture inspection
   limits stay bounded independently. A hidden 5120x72 window is checked at both
   internal resolution scales, including readback and D3D11 validation.

Third correctness pass - 2026-11-01

Revisited CPU instruction lowering, shared-memory helpers, native object/file

boundaries. The XISO's embedded executable passes target verification again.

Additional findings

1. REP MOVS overlap was decided from guest virtual addresses. Two distant guest
   aliases can refer to the same overlapping RAM. The helper incorrectly selected
   memmove in that case, preserving a snapshot instead of reading earlier writes
   as the original repeated instruction does. It now compares resolved backing
   addresses, retaining element order for forward and reverse harmful overlaps.
   Original _memmove 30D820 compares guest pointers at 30D834/30D838 and takes
   the REP MOVSD path at 30D853 for the aliased case. Its complete bounded CFG
   contains 231 instructions. Before the fix, the native CPU probe of that actual
   routine copied successive input words through the alias; the expected result
   repeats its first word after each overlapping write. The new diagnostic also
   checks the returned guest address, three alias pairs and reverse copying.

2. Append-only writes were treated as ordinary positioned writes. The service
   sought using an offset that append-only handles must ignore and calculated
   the reported ending position from that ignored offset. Such handles also do
   not need a seek operation to append. Both synchronous and asynchronous writes
   now resolve append-only requests to EOF, leave native appending to the native
   handle, and report the resulting synchronous position. Diagnostics append
   actual XISO-derived header bytes with a supplied zero offset and inspect the
   resulting prefix, suffix, size, status and guest file-object position.
   Original SDK write call 30424E uses NtWriteFile IAT 347558 (ordinal 236).

3. File-opening paths kept GENERIC_READ/WRITE/EXECUTE/ALL request bits rather
   than expanding them to file-specific rights. Among other consequences, a
   GENERIC_ALL request bypassed the disc's read-only access mask and access
   queries returned unresolved generic bits. The same file-rights mapping is
   required before disc validation and native file creation. This also keeps
   sharing checks and append-only detection based on concrete access rights.
   Execute-only opens also bypassed read-sharing restrictions. Read sharing now
   accounts for both data and execution access, with the corresponding packed
   FILE_OBJECT access/share bits kept consistent. The data-read service still
   requires FILE_READ_DATA; execution access does not grant direct data reads.
   Metadata-only opens are excluded from data-sharing restrictions in both
   directions, and publish no data/share access bits. The full-access native
   diagnostic compares against a direct Windows open instead of assuming this
   account can obtain ownership-changing rights on the host file.

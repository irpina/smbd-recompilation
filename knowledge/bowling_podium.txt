Root cause and correction
  The bridge wrongly required the first NV09F source-copy into a new native
  destination to fill complete rows from (0,0). NV062 supplies pitches and
  offsets; NV09F supplies source/destination points and rectangle dimensions.
  A valid rectangle need not cover a full pitched row or begin at the origin.

  Materialize the required destination extent, initialize it from guest RAM,
  and copy the requested native GPU rectangle. When texture binding, another
  blit, or a new depth view reveals a larger extent, preserve the existing GPU
  image and initialize only the newly exposed strips from RAM. Depth views share
  the color image. Linear RGB565 binding uses the verified NV097 format 0x11.

  Initialization is an AOT point-sampled native pass so scaled and MSAA surfaces
  receive the correct pixels and alpha, without gameplay GPU readback. Temporary
  upload storage is bounded by the existing image dimension limits. Uploads occur
  on materialization/growth, not on every draw. Capture/replay records these RAM
  initialization writes in their original order.

  Growing a sampled texture can flush queued draws. Resolve the texture state
  before reserving the next draw slot so that flush cannot leave the next draw
  in a discarded slot. The diagnostic checks two different queued draw counts
  and the following draw's actual texture handle across this flush.

  The error-screen loop also wrongly tried to display an active auxiliary target,
  producing the second error in the supplied log. It now displays the last
  published frame, with a cleared main image as the pre-publication fallback.

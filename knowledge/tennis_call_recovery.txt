Replay issue and correction
1EAC70 captures all four private records, their separate child actors,
and the ball into a 171C-byte slot. 1EAD30 restores them. Allocation
1EAB60 reserves 181 slots; recording 1EAF70 uses only indices 0..179,
writes before incrementing and sets full (+21C) only at the first wrap.
Recording reset 1EAE70 resets head/full, retaining the allocation.

1EAEB0 stops recording, saves the end in +218, and selects replay start
zero for a nonfull history. Full histories already have every selectable
slot initialized. Replay-eligible point endings occur after an enabled
post-serve physical pass; capture precedes that pass. The capture/parent
lifetime audit establishes at least one initialized slot for a nonfull
eligible replay, including pause transitions. No 61/51-frame minimum is
assumed here.

1F09EF starts playback. During the 60/50-frame fade, 1F0AD6 tail-jumps
to cursor helper 1EB0C0. That helper increments +210, compares with +218,
and returns 1 on completion. The fade ignores that result. Its next
frame's 1EB110 restores the selected slot unconditionally when storage
exists. The ordinary playback phase, by contrast, consumes completion
and clears playback before another restore.

The recompiler now preserves the last captured index when that fade-only
tail path returns completion for a nonfull history. It leaves the helper's
registers, flags, return result and stack unchanged, and keeps the original
fade timer. The ordinary playback phase then consumes completion normally.
Full histories retain their original wrap/advance behavior: their initial
end crossing is intentional, and every slot is initialized. Histories that
outlast the fade execute unchanged. This is an explicit bounds correction
to the recompiled game, not a claim that the original executable proves a
minimum rally length. Original heap allocation can request MEM_NOZERO;
unrecorded slots must not be assumed zero.

The correction is limited to functions containing the original 1F0AD6
tail and verified 1EB0C5/FD/108/10E instructions. The standalone cursor
helper is unchanged. Together with write-before-advance capture, this
preserves the private state/callback domains through every restored slot.
No new runtime instruction decoding, callback guessing or no-op handler
is introduced.

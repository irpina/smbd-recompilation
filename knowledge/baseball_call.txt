Root cause and original publication proof
  The previous UI callback catalogue followed direct row pointers but omitted
  a callback installed through an array of row pointers returned by 000ECB00.
  The old caller guard correctly stopped a target absent from that catalogue.

  ECB00's EAX is a count; its stack argument selects the initial array slot.
  It uses the Baseball master pointer at 007700A4 and the pointer array at +338.
  Every nonnull replacement element comes from original 736C0/73620, which
  allocates and clears one row in the same 80-element UI pool. Its return value
  points at the first selected pointer-array element, not at a row itself.

  Original builder 000F3E40 supplies count 5 and initial slot 50. It advances the
  returned pointer array by four bytes and loads its rows 1, 2 and 3. Instruction
  000F3EC3 is B9A03A0F00 (MOV ECX,000F3AA0). ECX remains unchanged through:
    000F3EC8  894E38  MOV [ESI+38],ECX
    000F3EFE  894E38  MOV [ESI+38],ECX
    000F3F36  894A38  MOV [EDX+38],ECX
  These install the draw callback in three UI rows. The target word begins at
  000F3EC4. The existing target_literals schema stores this original word's
  address, not the callback value itself.

  Independent native references locate exactly 34 direct ECB00 call sites.
  Their 28 distinct indexed owner entries were analyzed in one bounded set,
  at most 1024 instructions per owner; none exhausted its budget. Every call's
  address, original bytes and ECB00 target match the corresponding owner CFG.
  An inventory of all executable-address constants outside control transfers
  in these builders contains only F3EC3's F3AA0 publication. The existing
  width-aware UI header writer inventory also identifies all three stores.
  This covers the missed construction family rather than admitting a target
